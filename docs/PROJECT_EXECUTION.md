# 本地项目执行与长任务验收

2026-10-21：针对 #91 与 #104 的工程分析。本文描述差距与拟议实现，**不是已经交付的项目执行能力**。

## 当前边界

- Studio `/api/run` 从应用数据目录启动工作流；输入里的项目路径只是文本，不是已经授权和挂载的项目工作区。
- `ClaudeCodeConnector` 默认在临时空目录启动，并传 `--tools ''` 禁用工具。这避免普通内容工作流意外加载真实项目记忆，也意味着它不会因为提示词要求就实际读取或修改项目。
- `AO_CLI_INHERIT_CWD=1` 只影响启动目录，不会自动建立项目权限边界或重新启用工具，不能当作 #91 的完整解决办法。
- `FileJobStore` 保存任务状态、请求去重与事件，现有 `--resume` 复用步骤产物；二者都不是项目环境已满足目标的证明。服务重启后的自动恢复、worker 租约与统一队列仍未实现。
- `acceptance` 依赖模型评价，未通过可以作为质量告警；`assert` 检查产出结构。它们不能替代真实项目测试、进程健康检查或独立环境核验。

## #91 的最小完整流程

1. 用户选择项目根目录。服务端校验目录、解析真实路径，记录本次任务的工作区授权；明确哪些内容可发送给模型。单独处理符号链接、嵌套仓库和 Windows 路径，不仅靠字符串前缀判断包含关系。
2. 只读预览计划文件和有限文件清单；跳过凭证、构建缓存、二进制与超限内容。先展示将读取的范围，不扫描整块磁盘，也不把整个目录自动打包给模型。
3. 计划转为明确的文件变更与命令清单。新增与原计划不同的写入、命令或联网动作时重新批准；普通内容工作流继续保持现有连接器行为。
4. 在隔离的工作树或用户明确选择的工作区执行；记录变更前状态，保护已有未提交改动。回滚不使用覆盖用户文件的盲目 reset/clean；不能隔离的操作明确标出不可回滚部分。
5. 收集真实命令退出码、日志、差异、测试结果和服务健康检查。测试命令本身也属于可执行操作，审核角色不能以“只读核验”为由绕过授权。
6. 显式停止时终止任务进程树。续跑先核对工作区、计划修订与已验证证据；状态未知的命令不自动重放。停止、启动失败与核验失败不得显示为项目已完成。

首个验收样例使用临时 Git 仓库：读取计划 → 批准一项修改 → 执行确定性测试 → 查看差异及真实结果。必须覆盖拒绝越界路径、取消审批、保留旧改动、测试失败、运行中停止、外部改动后的恢复冲突。

## #104 的参考价值

[LongHorizon-Harness](https://github.com/AMAP-ML/LongHorizon-Harness) 将长期任务分为管理、执行与核验阶段，把目标和已验证进展保存在执行上下文之外。[论文摘要](https://arxiv.org/abs/2608.01964)解释了这一设计。其主仓库为 MIT 许可；本次仅检查设计和源码，没有复制代码或加入运行时依赖。

核对的固定上游版本：[eb87b66](https://github.com/AMAP-ML/LongHorizon-Harness/tree/eb87b66ed9604e0007cadb2fa58975d24da89669)，参考入口：

- [auditor_agent.py](https://github.com/AMAP-ML/LongHorizon-Harness/blob/eb87b66ed9604e0007cadb2fa58975d24da89669/src/lh_harness/auditor_agent.py)
- [AgentAdapter](https://github.com/AMAP-ML/LongHorizon-Harness/blob/eb87b66ed9604e0007cadb2fa58975d24da89669/src/lh_harness/adapters/base.py)

| 需要补足的能力 | AO 当前可复用部分 | 仍需实现 |
| --- | --- | --- |
| 长期目标与已核实进展 | 任务 UUID、快照哈希、步骤 metadata | 独立 TaskBrief 修订、证据目录与 verified/unverified 区分 |
| 每轮上下文控制 | DAG、步骤输入、角色提示词 | 只带已验证事实进入下一轮，拒绝把执行者自述自动写成事实 |
| 独立核验 | acceptance、assert、人工审批 | 针对真实工作区取证，核验权限受限，机械测试优先；角色独立不等于结果必然可靠 |
| 有界执行 | 现有步骤超时和有上限循环 | 任务级轮次、时间、费用预算，含核验开销；恢复或继续不得偷偷重置预算 |
| 可恢复副作用 | 步骤恢复、媒体任务 ID | 项目命令执行记录、运行所有权、重启后的外部状态核对与重复执行策略 |

## 实验与交付顺序

1. 先做不调用模型的证据协议实验：临时仓库、固定执行器和核验器，在“执行器说完成但测试失败”时拒绝推进 verified 状态。
2. 加入中断、工作区外部改动与核验不可用场景；预算耗尽或证据不完整时明确停在待确认，而不是完成。
3. 在 #91 的受控工作区执行链路成熟后，试接一个真实 CLI 后端。默认不自动启动长期循环，不把模型建议直接变成无限重试。
4. 比较完成率、误报完成次数、恢复重复执行次数、总耗时与费用，再决定是否引入上游适配或仅复用设计。上游基准成绩不能直接视为 AO 的实测提升。

#91 与 #104 继续保持打开，分别跟踪产品执行能力和实验方案；本文不把设计评估记为实现完成。
