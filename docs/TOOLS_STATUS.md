# 工具与模型：只读状态

Studio 的“工具与模型”入口位于 `/studio?tab=tools`，英文入口为 `/en/studio?tab=tools`。当前为尚未发布的新增功能。

此页读取 Claude Code `settings.json` 和 Codex `config.toml` 的全局摘要，复用现有安装检测和 AO 管理记录检查。查询接口为 `GET /api/tools/status`，响应禁止缓存。

- 端点只返回 HTTP(S) origin，隐藏用户信息、路径、查询参数和片段；不返回 API key、OAuth 内容或完整配置。
- 分别展示命令检测、配置读取结果、模型、显式供应商 ID、AO 管理标记、记录冲突及未完成事务。没有配置、读取失败、格式错误和读取期间变化不是同一种状态。
- “检测到命令”不保证版本兼容、登录或认证可用；此页不会执行 CLI 来查询版本，也不会调用模型测试连接。
- Claude 配置的 model 与 env 中的模型分开显示，不推断覆盖优先级；Codex 存在供应商表但未显式选择时，将端点标为待 CLI 解析，不猜默认供应商。
- AO 管理标记是配置记录，不是对来源身份的独立认证；未确认 AO 管理不代表配置异常或遭受攻击。
- 所示内容是全局文件摘要，不是运行中终端的实际连接证明。环境变量、项目设置、启动参数、配置 profile 等可以覆盖全局设置。未设置端点不证明官方账号已登录。
- 页面查看和刷新不切换供应商、不恢复事务、不创建配置备份；修改仍需进入既有供应商设置。刷新失败保留上一次结果并标记未确认，离线不发送工具状态请求。
- 新页面隐藏原顶栏的工作流供应商/模型选择器，避免误以为它会切换外部终端；原设置入口和工作流选择器在其他页面保留。

Codex 既有供应商设置的普通全局保存/恢复，现与历史接管/移除一样，要求配置版本校验。先读 `GET /api/config` 中 `providers["codex-cli"].configRevision`，提交 `POST /api/config` 时携带 `expectedRevision`。令牌绑定本引擎实例和 config/auth/AO 管理记录，重启或文件内容变化后必须重新读取并确认。缺少令牌返回 400 `CONFIG_PREVIEW_REQUIRED`；过期返回 409 `CONFIG_CHANGED`，前端保留输入并刷新状态，不自动重发。实际校验在事务锁内进行，继续遵守所有权检查、备份和回滚约束；直接调用写入器的既有代码可不传此可选参数。

保存确认说明目标主机、全局供应商/key 的修改、未指定模型时的恢复基线语义；恢复确认说明恢复记录字段，不保证官方登录。两者均不重启已运行会话。确认不会显示 key。恢复以字段值为基线，不能承诺任意 TOML 排版逐字还原（例如受管键等号旁的空格可能规整）。旧前端无法提供令牌时会被拒绝，应更新前端并刷新页面。

统一的跨工具变更预览、AO 默认/单任务作用范围选择、完整迁移报告和快捷切换仍待实现；Claude 的切换/恢复尚未接入同一预览版本机制。当前改动仅加固 Codex 既有全局操作，不代表以上功能全部完成。

验证：`npm run test:tool-status` 覆盖真实临时文件和 HTTP，只使用虚构凭证。额外浏览器验证应检查双语、深链/刷新/历史导航、外部修改读取、读取失败标记、离线请求以及没有非 GET API 请求。测试环境应设置 `AO_CLAUDE_DIR`、`AO_CODEX_DIR` 和 `AO_DATA_DIR`，避免使用真实用户配置。
